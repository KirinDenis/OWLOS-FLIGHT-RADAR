# ST7789

240x320 SPI panel, run in landscape 320x240 through `lcd_spi.c` ([bus-spi-strips](../bus-spi-strips.md)).
Sureness words as in [SKILL.md](../../SKILL.md). The start-up is the chip's own settings, as Espressif's
esp_lcd driver does it: reset, sleep out, 16-bit pixels, MADCTL, inversion, normal mode, display on.

## Where it is, and its MADCTL

The ST7789s met here are all in the "MX different from MY" family: landscapes 0x60 and 0xA0, with BGR 0x68
and 0xA8.

- **2.8" CYD v3** ("7789" on the listing): RGB, MADCTL 0xA0 (MY|MV), inversion on. Against v1's ILI9341 it is
  RGB not BGR and mirrored on one axis, so MADCTL loses BGR and MX: 0xE8 to 0xA0. Written into its table, not
  `LCD_MADCTL`, because the same build starts the ILI9341s with 0xE8 [built: a viewer's v3 showed the
  symptom that made it]. Board file: [ili9341](../../../esp32-boards/references/boards/ili9341.md).
- **NM-CYD-C5** (ESP32-C5): MADCTL 0xA0 (MY|MV, the landscape most of its sources use), no inversion (every
  source agrees), RGB first and BGR behind BOOT: RGB in the maker's Arduino setup and most ports, BGR in its
  MicroPython demo [built]. Board file: [nmcydc5](../../../esp32-boards/references/boards/nmcydc5.md).
- **ZLX-ESP32-2** (ESP32-C5): MADCTL 0x60 (MX|MV), the maker's landscape, TFT_eSPI rotation 1; with the BGR bit
  that is 0x68, which is what the maker's factory test (TFT_eSPI 2.5.43) runs. No inversion, BGR first, RGB
  behind BOOT, 40 MHz [built, not run]. Board file: [zlx2](../../../esp32-boards/references/boards/zlx2.md).
- **Elecrow CrowPanel Advance 2.8"** (ESP32-S3, IPS): MADCTL 0xA0 (MY|MV, LovyanGFX rotation 3, the one
  Elecrow's demos run), `LCD_INVERT 1`. Elecrow's setup says `invert = true` and `rgb_order = false`, and
  `rgb_order = false` is LovyanGFX's BGR bit set, so BGR first, RGB behind BOOT [built]. Board file:
  [crowadv28](../../../esp32-boards/references/boards/crowadv28.md). FusionEdge drives the same board with
  LovyanGFX's `Panel_ST7789` [docs, its CrowPanel-Advance-2.8 options].
- Not ported: Guition JC2432W328C (ST7789 IPS by its JSON, ILI9341 in some batches; IPS means `LCD_INVERT 1`
  is the first guess), ESP32-2432S032 (3.2" ST7789 IPS, RGB), LilyGO T-Deck (320x240), Waveshare
  ESP32-C5-Touch-LCD-2.8 (reset and backlight behind a CH32V003 co-processor).

Inversion goes with the glass, not the chip: on for IPS (CrowPanel Advance, CYD v3), off on the NM-CYD-C5's
and the ZLX's.

## The tables

The CYD's v3, in the ILI9341 build's profile list:

```c
/* v3: an ST7789 on the chip's own settings (like Espressif's esp_lcd driver). against v1 it is RGB
 * not BGR and mirrored on one axis, so MADCTL loses BGR and MX: 0xE8 -> 0xA0. with the v1 start-up
 * a viewer's v3 showed light blue on white and upside down, which is exactly those three */
static const init_cmd_t INIT_V3[] = {
    { 0x01, 0, { 0 }, 150 },                                  /* software reset */
    { 0x11, 0, { 0 }, 120 },                                  /* sleep out */
    { 0x3A, 1, { 0x55 }, 10 },                               /* 16 bits a pixel */
    { 0x36, 1, { 0xA0 }, 0 },                                /* MY|MV, RGB */
    { 0x21, 0, { 0 }, 0 },                                   /* inversion on */
    { 0x13, 0, { 0 }, 10 },                                  /* normal display mode */
    { 0x29, 0, { 0 }, 20 },
};
```

The boards whose chip is an ST7789 (`LCD_CHIP_ST7789`): two profiles that differ in bit 3 only, the order per
board in `LCD_ORDER` ({ 0, 1 } RGB first, { 1, 0 } BGR first):

```c
/* ST7789 on the chip's own settings, as the CYD's v3: inverted on an IPS panel (CrowPanel
 * Advance), not on the NM-CYD-C5's (board.h LCD_INVERT). its two profiles differ in the colour
 * order only, BGR is bit 3 of MADCTL */
#ifndef LCD_INVERT
#define LCD_INVERT 0
#endif
#define ST7789_INV (LCD_INVERT ? 0x21 : 0x20)                 /* inversion on or off */
static const init_cmd_t INIT[] = {
    { 0x01, 0, { 0 }, 150 },                                  /* software reset */
    { 0x11, 0, { 0 }, 120 },                                  /* sleep out */
    { 0x3A, 1, { 0x55 }, 10 },                               /* 16 bits a pixel */
    { 0x36, 1, { LCD_MADCTL }, 0 },                          /* landscape, RGB */
    { ST7789_INV, 0, { 0 }, 0 },                             /* inversion as the panel wants it */
    { 0x13, 0, { 0 }, 10 },                                  /* normal display mode */
    { 0x29, 0, { 0 }, 20 },                                  /* display on */
};
static const init_cmd_t INIT_BGR[] = {
    { 0x01, 0, { 0 }, 150 },
    { 0x11, 0, { 0 }, 120 },
    { 0x3A, 1, { 0x55 }, 10 },
    { 0x36, 1, { LCD_MADCTL | 0x08 }, 0 },                   /* the same, BGR */
    { ST7789_INV, 0, { 0 }, 0 },
    { 0x13, 0, { 0 }, 10 },
    { 0x29, 0, { 0 }, 20 },
};
#define CHIP "ST7789"
```

- RAMWRC 0x3C, which the strip driver uses after the first strip of a frame: [built] on the ST7789, measured
  on the ILI9341, ST7796 and GC9A01.
- To learn from an owner of each built board: colours right at start, which landscape is upright, a clean
  clock.

## Reading other people's setups

- LovyanGFX's `rgb_order = false` is its BGR bit set, not RGB. `invert = true` is 0x21.
- Rotation numbers are per driver: LovyanGFX rotation 3 is MADCTL 0xA0 on the CrowPanel Advance; TFT_eSPI
  rotation 1 is MX|MV on the ZLX-ESP32-2.
