# 2.8" CYD, ESP32-2432S028R (build `ili9341`)

The "cheap yellow display" by Sunton, sold in three revisions with the same pins and three different screens.

- Build: `ili9341`, `RADAR_DISPLAY` 1 (`DISPLAY_ILI9341_320x240`), target esp32, the default of BUILD.BAT. It keeps the
  plain `build` folder and `firmware/sdkconfig` it always had.
- How sure: the build is the most run of all, but on the desk's 2.8" boards, which a photo showed to be LCDWIKI E32R28T
  (see [e32r28t](e32r28t.md)): same screen and touch pins, another LED and an amplifier on GPIO 4. No Sunton
  ESP32-2432S028R of any revision is recorded on the desk. So: the v1 start-up and every pin of the screen and touch are
  measured on the E32R28T; the v2 and v3 start-ups are built, values from rzeldent's files.
- Also takes this build: [e32r28t](e32r28t.md), [bruce-cyd](bruce-cyd.md). FusionEdge's `cyd28` build is for this
  board and the E32R28T.

## Chip, flash, USB

- Classic ESP32 ([esp32](../chips/esp32.md)), 4 MB flash, no PSRAM. The module is an ESP32-WROOM-32 by FusionEdge's
  README; the chip on the desk's boards read ESP32-D0WD-V3 (measured, on the E32R28T).
- USB: a CH340 to UART0 (measured on the desk's boards). v1 has micro USB, v2 USB-C, v3 both (rzeldent, docs).
- rzeldent's README adds that the W25Q32JV flash chip is not always mounted (docs).

## Screen

2.8" 320x240 SPI. Three panels under one name (rzeldent/platformio-espressif32-sunton, esp32-2432S028R, Rv2, Rv3):

- v1, micro USB: ILI9341, BGR, MADCTL 0xE8, no inversion. The start-up is measured (on the E32R28T).
- v2, USB-C: ILI9341 with its own power and gamma values, inversion on, MADCTL 0xE8. Built.
- v3, USB-C and micro USB, sometimes marked "7789": ST7789, RGB, mirrored on one axis against v1, MADCTL 0xA0, inversion
  on. Built. rzeldent's Rv3 JSON has no IPS flag and a NULL vendor config; the inversion comes from a viewer's v3, which
  on the no-inversion start-up showed a dark UI as light blue on white, upside down: wrong colour order, inversion and
  one axis, exactly the three differences. If a v3 shows a negative, that line is the first suspect.
- One build carries all three (`LCD_PROFILES 3`). A board that never picked one starts as v2, which most sold boards
  are (`LCD_ORDER { 1, 0, 2 }`). BOOT in the first 8 s after power on, or on the touch alignment page, goes v2, v1, v3
  and keeps the pick in NVS key "screen" (0 v1, 1 v2, 2 v3). `OWLOS SET {"screen":n}` does the same for scripts.
- The start-ups: ../board-code.md. The panels: ../../../esp32-lcd-touch/references/panels/ili9341.md and
  ../../../esp32-lcd-touch/references/panels/st7789.md.
- 40 MHz SPI: 80 MHz APB / 2. ViewOwl asks 50 and the divider lands on 40 anyway (measured).
- Strips of 24 rows. Since 0.16.1 the second core draws the lower half of each strip (`DISP_HELPER_HALF`), which costs
  only its 7 KB stack: a strip of its own with twice the DMA buffers, as the 3.5" has, would take about 60 KB this board
  does not have.

## Touch

XPT2046 resistive on its own pins, bit-banged so the LCD bus stays free (measured). Rough raw span 3700. 36 and 39 are
input-only pins, the board pulls the pen IRQ up. Driver: ../../../esp32-lcd-touch/references/touch/xpt2046.md.

## Buttons, LEDs, other parts

- BOOT 0, RST.
- RGB LED on the back, each colour low = lit: red 4, green 16, blue 17 (rzeldent's JSON; on the E32R28T red is 22).
  Red's pin is a setting because nothing on a board tells the two makers apart, see ../board-code.md.
- Speaker on 26 through an amplifier, light sensor 34, SD card on CS 5, MOSI 23, MISO 19, SCK 18 (docs). The stock
  CYD's amplifier is documented as working, gain about 14.5 with a 4k7 input (hexeguitar/ESP32_TFT_PIO, docs).
- Free pins: CN1 has GND, 22, 27, 3.3V. P3 has 35 (input only), 22, and 21, which is the backlight. P1 is TX 1, RX 3.
- OWLOS Thermo Relay's wiring on CN1: IO27 a DS18B20 with 4.7k to 3.3V, IO22 the relay (measured on the desk's board).

## Pins

- LCD: SCLK 14, MOSI 13, MISO 12 not used (a strapping pin, left alone), DC 2, CS 15, RST tied high, BL 21 (PWM).
- Touch: CLK 25, MOSI 32, MISO 39, CS 33, IRQ 36.

## board.h

```c
#if RADAR_DISPLAY == DISPLAY_ILI9341_320x240
/* ESP32-2432S028R "cheap yellow display". the one this was written on, all of it works */
#define DISP_LCD_SPI   1
#define LCD_CHIP_ILI9341 1
#define PIN_LCD_SCLK  14
#define PIN_LCD_MOSI  13
#define PIN_LCD_MISO  (-1)      // write only, leave strapping pin 12 alone
#define PIN_LCD_DC     2
#define PIN_LCD_CS    15
#define PIN_LCD_RST   (-1)      // tied high, so software reset only
#define PIN_LCD_BL    21        // backlight, PWM
#define LCD_SPI_HZ    (40 * 1000 * 1000)   // 80 MHz APB / 2. ViewOwl asks for 50, the divider ends up here anyway
#define LCD_MADCTL    0xE8      // landscape for this panel: MY|MX|MV|BGR, same as ViewOwl
#define DISP_STRIP    24        // rows a strip: 240 / 24 = 10 strips
/* the second core draws the lower half of every strip while this one draws the upper (main.c). a
 * strip of its own and twice the DMA buffers, as the 3.5" has them, would take ~60 KB this board
 * does not have to spare: this way it costs its stack */
#define DISP_HELPER   1
#define DISP_HELPER_HALF 1
/* XPT2046 has its own pins here, we bit-bang it, cheap and the LCD bus stays free.
 * 36 and 39 are input only pins */
#define TOUCH_XPT_BITBANG 1
#define PIN_T_CLK     25
#define PIN_T_MOSI    32
#define PIN_T_MISO    39
#define PIN_T_CS      33
#define PIN_T_IRQ     36
#define PIN_BUTTON     0        // BOOT
// TODO: board speaker for geiger like clicks while hunting
/* the same name is sold in three revisions with the same pins and three different screens
 * (rzeldent/platformio-espressif32-sunton, esp32-2432S028R / Rv2 / Rv3):
 *   v1  micro USB      ILI9341, BGR, our MADCTL 0xE8, no inversion. the one this was written on
 *   v2  USB-C          ILI9341 with its own power and gamma values, colour inversion on
 *   v3  "7789"         ST7789, RGB, mirrored on one axis against v1, inversion on
 * nobody knows which one he has, so all three are in this build (lcd_spi.c, LCD_PROFILES; the
 * list keeps v1 first, boards save its index). a board that never picked one starts as v2: most
 * of them sold are v2. BOOT goes v2 -> v1 -> v3 and round again, see main.c */
#define LCD_PROFILES   3
#define LCD_ORDER      { 1, 0, 2 }
```

The comment's "the one this was written on" is older than the finding that the desk's boards are E32R28T. The LED's
green and blue come from the shared tail of board.h (../board-files.md).

## sdkconfig and partitions

`sdkconfig.defaults` + `sdkconfig.defaults.esp32`: CPU 240, flash QIO 80 MHz, 4 MB, `partitions.csv` (app 2 MB, tiles
1.94 MB). Lines in ../board-files.md. App 1,210,000 bytes (built, 2026-11-19).

FusionEdge's `cyd28` build for the same board: Arduino, DIO 40 MHz, 4 MB, `partitions_4mb.csv`, no PSRAM, a screen of
its own drawn two rows at a time, sound from the DAC on 26 (see [e32r28t](e32r28t.md)).

## Measured

All on the desk's 2.8" boards (E32R28T), the numbers are in [e32r28t](e32r28t.md).

## Traps

- "ESP32-2432S028" with no letter does not say R (resistive) or C (capacitive); this build is for R. A board sold under
  that name was a C3 clone (its ROM line said esp32c3) and took the round build.
- Wrong colours or mirrored on any 2.8": the wrong profile, BOOT in the first 8 s. First suspect for any "looks wrong"
  report.
- A GPS kit on TX and RX breaks flashing: [bruce-cyd](bruce-cyd.md).
