# AXS15231B touch half

The AXS15231B display controller on the Guition JC3248W535 has its touch built in, on I2C at 0x3B. Everything
here is [docs]: FusionEdge's `src/displays/lgfx/touch_axs15231b.h` (a LovyanGFX touch class), tested on a real
board by a FusionEdge contributor, not run here. Sureness words as in [SKILL.md](../../SKILL.md). The display half:
[panels/axs15231b](../panels/axs15231b.md).

## Reading a point

- Write an 11-byte read command: `0xB5, 0xAB, 0xA5, 0x5A, 0x00, 0x00, len_hi, len_lo, 0x00, 0x00, 0x00`, where
  len is the reply's length: 6 bytes a point plus 2, so 8 for one point.
- Then read that many bytes. Byte 1 is the number of touches; 0 means none.
- The point starts at byte 2: its event is the top nibble of byte 2, and only events 0x04 and 0x08 count. X is
  `((b[2] & 0x0F) << 8) | b[3]`, Y `((b[4] & 0x0F) << 8) | b[5]`, size in b[6].
- Values past the panel's raw maximum are dropped.
- The panel stands while the picture lies: the class returns `x = raw_y_max - raw_y`, `y = raw_x`.

## Wiring as FusionEdge sets it

- Its own I2C port (port 1), SDA, SCL and INT on GPIOs, no reset pin, INT with a pull-up, not shared with other
  devices. The pins: [jc3248w535](../../../esp32-boards/references/boards/jc3248w535.md).
- FusionEdge's options file defines `TS_AXS15231_FIX` for this touch, but no source reads it: a leftover.
