# ESP32-2432S032, the 3.2" CYD (build `esp2432s032`)

Sunton's 3.2" board in the CYD family: a classic ESP32, an ST7789 240x320 IPS screen, sold as R (resistive XPT2046),
C (capacitive GT911) and N (no touch). Every pin is the 3.5" ESP32-3248S035's ([st7796](st7796.md)); only the screen
differs.

- Build: `esp2432s032`, `RADAR_DISPLAY` 20 (`DISPLAY_2432S032_320x240`), target esp32. New in the 0.17 beta, so the
  site flashes it the beta only (flow.js `inStable`).
- How sure: built 2026-11-25, not run on one. Asked that day in a comment with two photos (the back marked
  ESP32-2432S032, a CYD logo, USB-C). The asker had flashed the 3.5" build: a garbled, flickering screen (their report).
  Next day they said "32R", while the seller's box says "3.2-inch capacitive touch": a version told by the owner and a
  version on the box can disagree, which is why the build asks for both touch chips instead of trusting either.
- Why the 3.5" build garbles it [reasoned]: the same pins, so it starts and drives the screen, but it sends an ST7796's
  start-up and a 480x320 picture to a 240x320 ST7789. No harm to the board: every pin does the same job.

## Chip, flash, PSRAM, USB

- ESP32-WROOM-32 ([esp32](../chips/esp32.md)), 4 MB flash, no PSRAM. USB-C through a USB to serial chip, as the other
  CYDs. App 1,240,720 bytes (0x12EE90), 41% of the 2 MB slot free (built).

## Screen

ST7789 240x320 IPS, RGB, inverted (rzeldent's JSONs: `DISPLAY_IPS`, `ESP_LCD_COLOR_SPACE_RGB`, no swap or mirror in
portrait; the maker's spec sheet: ST7789, 240x320, IPS, 64.8 x 48.6 mm shown, so square pixels). SPI mode 3
(`LCD_SPI_MODE 3`, the radar's other ST7789s run 0): the maker's Arduino_GFX demos and rzeldent both drive it so. 40 MHz;
the maker's demos ask 80, rzeldent 24. `LCD_MADCTL 0xA0` (MY|MV, RGB): the maker's demos' landscape (Arduino_GFX
rotation 3), SET's FLIP turns it over. RGB first, BGR behind BOOT (`LCD_ORDER { 0, 1 }`): RGB in rzeldent and the
Arduino_GFX demos, BGR only in the maker's one TFT_eSPI User_Setup.h, whose header is copied from an ILI9341 file. The
screen's reset is the ESP32's EN; the backlight an AO3402 MOSFET on 27, high is on.
Strips of 24 rows with the second core on the lower half of each, as on the 2.8" CYD (the same chip, the same picture
size). Panel: ../../../esp32-lcd-touch/references/panels/st7789.md.

## Touch

As the 3.5": `TOUCH_GT911_TOO` asks for a GT911 on SDA 33, SCL 32 first (the C; its reset 25 and interrupt 21 left
alone), at 0x5D and 0x14, and gives the pins back when nobody answers; then an XPT2046 on the screen's bus, CS 33, pen
IRQ 36 (the R). The N has none: BOOT and the site. Both addresses matter here: the schematic puts the GT911's INT (21,
through 0 ohm) on the 4-pin CN1 too, with a 10K pull-up, so a GT911 that wakes with INT high may answer at 0x14. ../../../esp32-lcd-touch/references/touch/xpt2046.md, gt911.md.

## Other parts

RGB LED 4, 16, 17 (anodes to 3.3 V through 1K, low = lit, the CYDs' red choice in SET's LED tab), speaker 26 through an
FM8002A (not used), light sensor 34, SD card on CS 5, MOSI 23, SCLK 18, MISO 19 (its own bus, not used). BOOT 0. Also a
lithium battery connector with a charger, a DHT11 socket, CN1 (3.3 V, 21, 22, GND) and P3 (21, 22, 35).

## Pins

LCD MOSI 13, MISO 12 (only the touch reads it), SCLK 14, CS 15, DC 2, no reset, BL 27. XPT2046 CS 33, IRQ 36. GT911 SDA 33,
SCL 32, RST 25, INT 21. LED 4, 16, 17. BOOT 0.

## board.h

```c
#elif RADAR_DISPLAY == DISPLAY_2432S032_320x240
#define DISP_LCD_SPI   1
#define LCD_CHIP_ST7789 1
#define PIN_LCD_SCLK  14
#define PIN_LCD_MOSI  13
#define PIN_LCD_MISO  12        // only the touch reads it
#define PIN_LCD_DC     2
#define PIN_LCD_CS    15
#define PIN_LCD_RST   (-1)
#define PIN_LCD_BL    27
#define LCD_SPI_MODE   3
#define LCD_SPI_HZ    (40 * 1000 * 1000)
#define LCD_MADCTL    0xA0      // MY|MV, RGB: the maker's demos' landscape. FLIP turns it over
#define DISP_STRIP    24
#define DISP_HELPER   1
#define DISP_HELPER_HALF 1
#define LCD_INVERT     1
#define LCD_PROFILES   2
#define LCD_ORDER      { 0, 1 }
#define TOUCH_XPT_SPI 1
#define PIN_T_CS      33
#define PIN_T_IRQ     36
#define PIN_BUTTON     0
#define TOUCH_GT911_TOO 1
#define PIN_I2C_SDA   33
#define PIN_I2C_SCL   32
```

In core/config.h it joins the 320x240 boards (GFX_W, GFX_H), `RADAR_TOUCH_CAL`, `RADAR_HAS_LED`, `RADAR_LED_RED_PIN`, and
in core/ui_int.h `WX_HUD`.
