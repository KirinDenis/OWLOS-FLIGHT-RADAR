# Guition JC3248W535, 3.5" AXS15231B QSPI (FusionEdge build `jc3248w535`)

A cheap, common 3.5" 480x320 on an ESP32-S3, its AXS15231B display and touch controller on a QSPI bus. Some batches
ignore the window commands: whole frames from PSRAM.

- Build: FusionEdge's `jc3248w535` (AXS15231B_options). No Flight Radar build: the radar has no QSPI driver yet.
- How sure: docs for this skill. FusionEdge's folder README says the driver's stabilization and an overnight stability
  test were done on one by a contributor it credits (measured there, not here). Pins also in rzeldent's JSON.

## Chip, flash, PSRAM

ESP32-S3 16 MB flash, 8 MB OPI PSRAM ([esp32-s3](../chips/esp32-s3.md)). rzeldent's JSON says PSRAM `qio_opi`.

## Screen and touch

- AXS15231B on QSPI: CS 45, SCK 47, D0 21, D1 48, D2 40, D3 39, RST none, backlight 1. rzeldent adds TE 38, 40 MHz.
  FusionEdge runs QSPI at 40 MHz for writes and 16 MHz for reads (other displays there: 27 and 12). Panel:
  ../../../esp32-lcd-touch/references/panels/axs15231b.md.
- Touch: the AXS15231B's own, on I2C SDA 4, SCL 8, INT 3, no reset (`TS_MODEL_AXS15231B`, `TS_AXS15231_FIX`).
  ../../../esp32-lcd-touch/references/touch/axs15231b.md. rzeldent's JSON for the N model names no touch.
- What made it stable in FusionEdge (its README): no DMA for the QSPI frame transfer; wait for each 12,800-pixel staging
  block before reusing it; at most one full frame every 50 ms; LovyanGFX's own framebuffer display path off; the whole
  CASET window sent again before every frame.

## Other parts

- `USE_BUILTIN_LED` must be false on this board (FusionEdge, "IMPORTANT").
- PCM5102A I2S: DOUT 14, BCLK 9, LRC 46. Encoder: 15, 16, button 7.
- SD card on FSPI (the QSPI display takes the other host): SCK 12, MISO 13, MOSI 11, CS 10 at 4 MHz (from the
  schematic, by the config's comment).
- IR: GPIO 38 is not an RTC pin, so waking from sleep needs GPIO 2, rewired on the PCB.
