# ILI9488

320x480 panel. Over SPI it does not take 16-bit pixels. Not in OWLOS Flight Radar: it came up as a request
and nobody has run it here. Sureness words as in [SKILL.md](../../SKILL.md).

## Where it is

- Asked for: an ILI9488 wired by hand to an ESP32-S3 by someone in the group. From their drawing, a small
  picture, so not sure of every digit: no SDO and no PEN pin, the XPT2046 on pins of its own. Board file with
  the wiring: [ili9488-diy](../../../esp32-boards/references/boards/ili9488-diy.md). Still to learn: the digits
  confirmed, which S3 board (flash, PSRAM), 3.5" or 4.0", whether they would test.
- FusionEdge drives it through LovyanGFX's `Panel_ILI9488` on three boards: its own ESP32-S3 DevKitC with an
  ILI9488 module, the 4D Systems gen4-ESP32 3.5" CT (ESP32-S3, FT6X36-family touch at 0x38, panel reset on a
  GPIO) and an ESP32-WROVER N16R8 board; SPI at 27 MHz write, 12 MHz read; inversion a stored user setting
  [docs: another project's working builds, not run here]. Board files:
  [s3-ili9488](../../../esp32-boards/references/boards/s3-ili9488.md),
  [gen4-35ct](../../../esp32-boards/references/boards/gen4-35ct.md),
  [wrover-n16r8](../../../esp32-boards/references/boards/wrover-n16r8.md).
- Not ported: Elecrow CrowPanel 3.5 (ILI9488, 18-bit pixels over SPI).

## What it needs [docs, TFT_eSPI's driver]

- `0x3A 0x66`: 18 bits a pixel, sent as 3 bytes, the top 6 bits of each. 0x55 is for parallel and RPi style
  boards.
- A strip is 1.5 times the bytes: `GFX_W * rows * 3`, 11,520 at 480 x 8; `max_transfer_sz` and the DMA buffers
  to match. No byte swap.
- 480x320 x 3 bytes at 40 MHz is 92 ms on the wire, 10.8 fps at most, against 61 ms for the 16-bit ST7796.
- A hardware reset on a GPIO: lcd_spi.c only sends 0x01.
- An XPT2046 with no PEN wire: `irq_init` and the pin read need `#ifdef PIN_T_IRQ`; with `s_irq` 0 every sample
  asks the chip, which is the path a lying pin takes already ([xpt2046](../touch/xpt2046.md)).
- Landscapes 0x28 (MV|BGR) and 0xE8, the "MX equal to MY" family, from TFT_eSPI's ILI9488_Rotation.h.

```c
    { 0xF7, 4, { 0xA9, 0x51, 0x2C, 0x82 }, 0 },               /* adjust control 3 */
    { 0x11, 0, { 0 }, 120 },                                  /* sleep out */
    { 0x29, 0, { 0 }, 25 },                                   /* display on */
};
```

## What changes in lcd_spi.c [reasoned, the plan on file in BOARDS-WANTED.md]

```c
/* the strip: 3 bytes a pixel, the panel takes the top 6 bits of each. no byte swap, no 565 */
static void pack666(const canvas_t *cv, uint8_t *o)
{
    for (int i = 0; i < GFX_W * cv->h; i++) {
        uint32_t p = cv->px[i];
        *o++ = (uint8_t)((p >> 16) & 0xFC);
        *o++ = (uint8_t)((p >> 8) & 0xFC);
        *o++ = (uint8_t)(p & 0xFC);
    }
}
/* sizes: strip_bytes = GFX_W * DISP_STRIP * 3, the DMA buffers and max_transfer_sz with it, and
 * bytes = GFX_W * rows * 3 in disp_strip */

/* hardware reset, before run_profile, as lcd_ili9486.c does it */
#if PIN_LCD_RST >= 0
    gpio_config_t rst = { .pin_bit_mask = 1ULL << PIN_LCD_RST, .mode = GPIO_MODE_OUTPUT };
    gpio_config(&rst);
    gpio_set_level(PIN_LCD_RST, 0);
    vTaskDelay(pdMS_TO_TICKS(10));
    gpio_set_level(PIN_LCD_RST, 1);
    vTaskDelay(pdMS_TO_TICKS(120));
#endif
```

- The dither in `gfx_pack565` is not needed at 6 bits a colour. Whether it still helps dark gradients is to be
  seen.
- 0x3C RAMWRC: check it on the glass; the fallback is a window and 0x2C for each strip as the ILI9486 driver
  does.
- Inversion is not in this table, so `remind()` would send no 0x20 or 0x21. A panel that needs 0x21 gets it
  added to the table.
- The asker's wiring: the bit-banged touch path with no `PIN_T_IRQ`: guard `irq_init` and the pin read with
  `#ifdef`, leave `s_irq` 0, and every sample asks the chip.
