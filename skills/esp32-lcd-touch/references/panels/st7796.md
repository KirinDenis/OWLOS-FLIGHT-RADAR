# ST7796

320x480 SPI panel, run in landscape 480x320 through `lcd_spi.c` ([bus-spi-strips](../bus-spi-strips.md)).
Sureness words as in [SKILL.md](../../SKILL.md).

## Where it is

- 3.5" CYD ESP32-3248S035, R (XPT2046 on the LCD bus) and C (GT911) versions. The one on our desk is sold as a
  CYD but is an LCDWIKI E32R35T (ESP32-32E): same screen and touch pins, red LED on GPIO 22 [measured]. A
  second 3.5" on the desk runs it too [measured]. The C version's GT911 [built]. Board files:
  [st7796](../../../esp32-boards/references/boards/st7796.md),
  [e32r35t](../../../esp32-boards/references/boards/e32r35t.md).
- FusionEdge runs the E32R35T with LovyanGFX's `Panel_ST7796`, rotation 3, inversion off, the XPT2046 on the
  panel's bus read through MISO 12 [measured with FusionEdge on the board here].
- Not ported: WT32-SC01 (3.5" ST7796, FT6336, ESP32 with PSRAM).

## Settings that work

- MADCTL 0xE8 (MY|MX|MV|BGR), from ViewOwl (an earlier firmware of ours) [measured].
- No inversion [measured].
- 40 MHz, MISO 12 used because the touch reads it.
- Strips of 6 rows (was 8; WiFi Radar 12): [bus-spi-strips](../bus-spi-strips.md) says why.
- Measured: WiFi Radar 8 fps (118 ms a frame, 24 KB heap left). Flight Radar: map look 81 ms, 61 of it on the
  wire; radar look 98 ms with the second core; the weather look 8 fps, 111 ms (later 9 to 12 fps, 80 to 106
  ms), heap 34 to 52 KB.

## The table

From Espressif's esp_lcd_st7796 1.3.5 (Apache 2.0), as ViewOwl uses it. The 0xF0 pairs unlock and lock the
extended command set.

```c
static const init_cmd_t INIT[] = {
    { 0x01, 0, { 0 }, 120 },                                  /* software reset (no RST pin) */
    { 0x11, 0, { 0 }, 100 },                                  /* sleep out */
    { 0x36, 1, { LCD_MADCTL }, 0 },
    { 0x3A, 1, { 0x55 }, 0 },                                /* 16 bits a pixel */
    { 0xF0, 1, { 0xC3 }, 0 },                                /* command set unlock, part 1 */
    { 0xF0, 1, { 0x96 }, 0 },                                /* and part 2 */
    { 0xB4, 1, { 0x01 }, 0 },
    { 0xB7, 1, { 0xC6 }, 0 },
    { 0xE8, 8, { 0x40, 0x8A, 0x00, 0x00, 0x29, 0x19, 0xA5, 0x33 }, 0 },
    { 0xC1, 1, { 0x06 }, 0 },
    { 0xC2, 1, { 0xA7 }, 0 },
    { 0xC5, 1, { 0x18 }, 0 },
    { 0xE0, 14, { 0xF0, 0x09, 0x0B, 0x06, 0x04, 0x15, 0x2F, 0x54, 0x42, 0x3C, 0x17, 0x14, 0x18, 0x1B }, 0 },
    { 0xE1, 14, { 0xF0, 0x09, 0x0B, 0x06, 0x04, 0x03, 0x2D, 0x43, 0x42, 0x3B, 0x16, 0x14, 0x17, 0x1B }, 0 },
    { 0xF0, 1, { 0x3C }, 0 },                                /* lock again */
    { 0xF0, 1, { 0x69 }, 0 },
    { 0x20, 0, { 0 }, 0 },                                   /* no inversion, like ViewOwl */
    { 0x29, 0, { 0 }, 20 },
};
#define CHIP "ST7796"
```

## Things met on it

- **Picture stood still after about a day**, cause not known, seen once. That is why `remind()` re-sends the
  safe commands every 5 s ([SKILL.md](../../SKILL.md), section 7). The power and gamma values sit behind the
  0xF0 unlock and are not repeated.
- **A frame a third slower** while the touch shared the bus, until the pen interrupt kept the touch off it
  ([xpt2046](../touch/xpt2046.md)).
- **Phantom taps after a restart** (the look changed by itself) came from single noisy touch reads; fixed by
  two reads in a row and a deaf time at power on ([xpt2046](../touch/xpt2046.md)).
- **The map came up empty** for 15 s now and then: memory in pieces too small for the tile reader. Strips of 6
  rows gave the maps 7 KB more.
