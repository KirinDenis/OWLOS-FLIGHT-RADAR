# ADS1015 (and ADS1115): four analog inputs on I2C

TI's ADC. On the OWLOS Air Quality board at 0x48: AIN1 the MQ135, AIN2 the MQ7, AIN3 the photoresistor, AIN0 unused. The old
notes said ADS1115; it is an ADS1015, 12 bit. From `code/aq_sensor_hw.c`; the board in `../air-quality.md`.

How sure: read on the board, the part told apart by its results. [measured] The data-rate and input-range notes are [docs].

## Reading one channel

The same address and registers for both parts. The code reads both the same way: the 12-bit part puts its result left-aligned,
so `raw * 6.144 / 32768` holds for both.

```c
// OS start, MUX AINch vs GND, PGA +-6.144 V, single shot, 128 SPS, comparator off
uint16_t cfg = (uint16_t)(0x8000 | (4 + ch) << 12 | 0x0000 | 0x0100 | 0x0080 | 0x0003);
i2c_wr(s_ads, 0x01, (const uint8_t[]){ (uint8_t)(cfg >> 8), (uint8_t)cfg }, 2);
for (int i = 0; i < 6; i++) {                                  // ~8 ms at 128 SPS
    vTaskDelay(pdMS_TO_TICKS(4));
    if (!i2c_rd(s_ads, 0x01, b, 2)) return 0;
    if (b[0] & 0x80) break;                                    // OS = 1: conversion done
}
i2c_rd(s_ads, 0x00, b, 2);
int16_t raw = (int16_t)(b[0] << 8 | b[1]);
*v = (float)raw * (6.144f / 32768.0f);
```

## Telling them apart

The ADS1015 never sets the low 4 bits of the result. After 20 reads with none set the firmware says ADS1015. [measured]

## From the datasheets, not checked on the board

- The data-rate bits 0x0080 mean 128 SPS on the 1115 and 1600 SPS on the 1015.
- The inputs must stay within the chip's own supply plus 0.3 V whatever the PGA range says. If MQ modules can reach 5 V, look at
  what the ADS runs on. [docs]

## What it is not

Not a voltmeter of the board's supply: nothing wires it to the 5 V rail. [measured]

## Traps

- The README's chip does not answer its way: read the part's own behaviour, never trust the old notes. [measured]
