# HDC1080: temperature and humidity on I2C

TI's humidity and temperature sensor. On the OWLOS Air Quality board at 0x40, where the old README said SI7021. From
`code/aq_sensor_hw.c`; the board in `../air-quality.md`.

How sure: read on the board, told apart by its id registers. [measured]

## Reading it

```c
// IDs: 0xFE reads 0x5449, 0xFF reads 0x1050. config 0x02: 0x1000 = heater off, both in one go, 14 bit each
const uint8_t p = 0x00;
i2c_tx(s_hdc, &p, 1);                       // the pointer alone starts it: temperature, then humidity
vTaskDelay(pdMS_TO_TICKS(20));              // 6.35 + 6.5 ms at 14 bit. before that it NACKs
i2c_rx(s_hdc, b, 4);                        // a plain read
s->hdc_t = (float)((b[0] << 8) | b[1]) * (165.0f / 65536.0f) - 40.0f;
s->hdc_rh = (float)((b[2] << 8) | b[3]) * (100.0f / 65536.0f);
// config bit 11 (b[0] >> 3 & 1): its supply is under 2.8 V
```

## What was found

- About 4.5 C hotter than the DHT22: it sits in the board's heat. So the DHT22 comes first, the user has an offset. [measured]
- It NACKs until the conversion is done: wait 20 ms, then a plain read.
- The chip at 0x40 is the one that sent ESP-IDF 5.5's `i2c_master` into an endless wait after a NACK, and the board into a
  restart loop. Hence the bit-banged bus with a limit on every wait (`../air-quality.md`). [measured]
- Config bit 11 says its supply is under 2.8 V: one of the board's power clues.
- It tells the CCS811 the temperature and humidity once a minute when it is there.

## Traps

- The README's chip does not answer its way: read the id registers (0x5449, 0x1050). [measured]
- Temperature 4.5 C high: board heat. DHT22 first, user offset. [measured]
